# AI-Disk-Assistant 冗余清理与结构优化计划

## 现状结论（已逐行核验）
项目约 2400 行核心代码，分层干净（models ← safety/metadata/cache ← privacy/config ← ai_advisor/cleaner/scanner/report ← cli/gui），无循环依赖、无未用 import。共定位 27 处冗余，核心问题：死代码 3 处、同名异值常量 2 组、复制粘贴流水线 3 组、默认值/版本号硬编码分叉多组。

## 改动方案

### 第 0 步：安全基线
- 项目当前无版本控制，先 `git init` + 提交当前状态作为重构前基线（便于随时回滚）
- 确认 python/pytest 环境（优先项目 .venv），跑通现有 8 个测试作为绿色基线

### 第 1 步：删除死代码
1. `ai_advisor.py:110-112` `_coerce_advice`（全项目无调用）
2. `cache.py:78-80` `AdviceCache.clear()`（无调用）
3. `scanner.py:205-212` `scan_candidates` 兼容包装 → 同步更新 `tests/test_scanner.py` 改用 `scan_with_stats`
- 版本号统一：`__init__.py` 1.2.1 → 1.3.0（与 pyproject.toml 对齐）

### 第 2 步：常量收拢（行为不变）
- 后缀常量全部集中到 `safety.py` 统一定义，scanner.py 改为导入：
  - `AUTO_DELETE_JUNK_SUFFIXES`（原 safety 版，不含 .bak——自动删除白名单）
  - `SIGNAL_JUNK_SUFFIXES`（= 上者 + .bak，仅用于扫描打分）——两组值的有意差异改用命名+注释固化，消除"同名异值"误改隐患
  - 打分用 `SIGNAL_ARCHIVE_SUFFIXES`（6 个）与内容分类用 `USER_ARCHIVE_SUFFIXES`（3 个）分开命名
  - `INSTALLER_SUFFIXES` 移入 safety.py
- reason 120 字符上限：models.py 定义 `REASON_MAX_LENGTH = 120`，ai_advisor.py:99（超限抛错）与 models.py:66（兜底截断）共用常量并注释两种策略的区别

### 第 3 步：提取公共函数
1. models.py 新增 `safe_fallback_advice(reason, source)` 工厂 → 替换 5 处重复兜底 Advice 构造（ai_advisor.py:232、257、297、360；scanner.py:184）
2. report.py 新增 `write_all_reports()` → 替换 3 处报告四连调用（cli.py:119-132、gui.py:397-400、gui.py:481-484），内部统一 mkdir+write 样板
3. ai_advisor.py 新增 `build_advisor(enable_ai, privacy_mode)` → 替换 3 处 Settings+HybridAdvisor 组合（cli.py:61-68、gui.py:378-379、389-390）
4. 合并两个响应解析函数中重复的 text-part 归一化逻辑（ai_advisor.py:121-137 vs 140-167）
5. `_apply_hybrid_guard` 两个近似分支合并（ai_advisor.py:305-324）

### 第 4 步：默认值单一来源
- CLI argparse 默认值改为引用 `ScanPolicy()` 字段（cli.py:39-44）
- GUI 天数/AI 上限默认值引用 ScanPolicy（gui.py:224-225）
- User-Agent 与 GUI 窗口标题从 `__version__` 派生（config.py 定义一次，替换 gui.py:198、210 及 config.py 内 3 处硬编码）
- 缓存路径默认值集中为 config.py 的 `DEFAULT_CACHE_PATH`（替换 config.py:157、174 与 gui.py:164）
- GUI `max_candidates=1000`（gui.py:394）提为具名常量 `GUI_MAX_CANDIDATES` 并注释：与 CLI 5000 的差异是有意的（GUI 列表刷新性能），不再是无声明分叉

### 第 5 步：功能分类注释（全部 13 个模块 + 2 个入口）
- 每个文件顶部加中文模块 docstring：一句话职责 + 分层位置 + 被谁使用
- 大文件加分节注释（ai_advisor：协议解析/校验/混合决策/HTTP 请求；gui：配置对话框/主窗口构建/后台任务/事件轮询；scanner：遍历/打分/主流程等）
- 有意保留项加"保留原因"注释：`accessed_time_ns`（仅报告导出用）、`advise_ai_only_many`（仅评测）、`AdvisorStats` token 统计（落盘 summary JSON）、CLI/GUI 各自的 TRASH 确认实现

### 第 6 步：输出两份文档
1. `docs/code-map.md`：分层架构图、每模块职责+关键函数行号、程序入口、"扫描→打分→AI 决策→报告"数据流说明
2. `docs/redundancy-report.md`：27 项冗余完整清单，每项标注处置结果（✅已修复 / 📌有意保留+原因 / 💡建议未执行）

### 第 7 步：全量验证
- pytest 全量通过
- `python -m compileall` 语法检查
- CLI 冒烟：临时目录造测试文件 → `python main.py scan <tmp> --no-ai` + `inspect` 单文件，确认报告产出
- GUI 导入冒烟 `python -c "import ai_disk_assistant.gui"`
- 可选：ruff check

## 明确不做（记录在冗余报告中）
- safety.py:104-128 查表化、scanner.py:85-90 打分分支循环化——可读性收益存疑，仅加注释
- `accessed_time_ns` / token 统计 / `advise_ai_only_many` 不删除（有明确用途）
- CLI 与 GUI 的 TRASH 二次确认不强行合一（终端输入 vs 对话框，UI 范式不同）

## 预期结果
消除 3 处死代码、11 处重复逻辑、2 组同名异值常量、4 处版本号分叉；核心逻辑净减约 80 行，新增中文注释约 200 行；8 个测试保持全绿，CLI/GUI 行为不变（除版本号显示）。
